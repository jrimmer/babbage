# Decisions (settled; reopen only on purpose)

| Date | Decision | Why |
|---|---|---|
| 2026-10-25 | All arithmetic is exact rationals on bigints. No f64 in the engine. | Precision is the top requirement. |
| 2026-10-25 | Irrationals (sqrt, trig, ln, pi) use 50 working digits, correctly rounded, always flagged approximate unless the result is exactly rational. | Maintainer choice. Symbolic is ticket 0001. |
| 2026-10-25 | UI is gpui. Engine is a separate UI-free crate. | Maintainer choice, matches casabon2. |
| 2026-10-25 | Anything needing an outside data source is post-v1 (tickets 0003 to 0010). | Maintainer rule. |
| 2026-10-25 | Result size cap is 2^20 bits. Over the cap is an error, never a silent approximation. Fallback is ticket 0002. | An unflagged approximation would break the precision promise. The 10,950-period daily compounding case fits and is exact. |
| 2026-10-25 | The exponent has no fixed cap. Only the predicted result size limits `^`. `0^n`, `1^n` and `(-1)^n` work for any integer n. | A fixed 4096 cap wrongly refused real finance cases. |
| 2026-10-25 | Default display rounding is half away from zero at 10 places. Half-even, toward zero and away from zero are available. | Matches the target screenshot. |
| 2026-10-25 | `0^0` is an error. | No single convention is safe. Revisit if it bites. |
| 2026-10-25 | A value that rounds to zero prints `0`, never `-0`, and is flagged inexact. | Avoids a misleading sign. |
| 2026-10-25 | Thousands separators are strict: `1,024` is a number, `1,2` and `1234,567` are errors. | A comma that is not a valid group is never silently merged into a number. |
| 2026-10-25 | No trailing-dot numbers: `5.` is an error. | Strictness over guessing. |
| 2026-10-26 | A percentage is stored as its fraction (10% is 1/10) and carries a `Kind`. Display multiplies by 100. | Keeps every percent operation exact rational arithmetic. |
| 2026-10-26 | Attached `%` (`10%`, `(1/2)%`, `10%%`) is a postfix on the value before it. A detached trailing `%` (`20/200 %`) means "as percent". | Both forms appear in the maintainer's docs and mean different things. |
| 2026-10-26 | Where the percentage docs are silent, the engine returns `UnsupportedOperation` instead of guessing: `10% x 10%`, any division involving a percentage, `10%^2`, `2^10%`. | A guess would be an unverifiable precision claim. Verify against the real app, then relax (ticket 0012). |
| 2026-10-26 | Fractions and decimals work wherever a percentage rate is expected in `of`, `on`, `off` and the `is ... of what` forms. | The maintainer's notes say a decimal or fraction can replace a percentage. |
| 2026-10-26 | Multi-word phrase forms apply to a whole line only, matched from a table (`phrase.rs`). `of`, `on`, `off` alone are infix operators; `of` equals `x`. | Keeps parsing iterative and the phrase list data-driven. Nested phrases are ticket 0013. |
| 2026-10-26 | Unknown words are an error (`UnexpectedWord`), not ignored. | Free text is ignored as labels in the intended behavior; that is row 9 and must be deliberate, not an accident of the parser. |
| 2026-10-26 | Money: each currency is its own dimension, so `$ + EUR` is `CurrencyRateNeeded`, never a number. Live rates are post-v1. A rate the user writes (`50 EUR in USD at 1.05 USD/EUR`, or `@`) works now. | Precision: a wrong rate is worse than no answer. |
| 2026-10-26 | `$` means USD. Other dollars: `A$`, `C$`, `NZ$`, `S$`, `HK$`, `NT$`, `R$`, `US$`. Region settings are ticket 0027. | The maintainer's notes ties `$` to the Mac region; this engine has none yet. |
| 2026-10-26 | Money shows its ISO 4217 digits (2, 0 for JPY, 3 for BHD); crypto and commodities show every digit. Declaration lines show money unrounded. | Matches the maintainer's `$999.00` and the variables notes. |
| 2026-10-26 | Default display abbreviates from 100,000 (`300k`, `3.3M`, `16.777216M`), moving the decimal point only. The threshold is inferred from the maintainer's `300k` and `16,384` examples. | Unverified against the app: ticket 0028. |
| 2026-10-26 | `$30 x 4 days` is `$120.00`: a price times a count of anything keeps the price's unit. | The maintainer's notes states it. |
| 2026-10-26 | Sheets: top to bottom. A line sees only lines above it. Subtotals stop at the previous subtotal, a heading or a divider; percentage lines apply to the subtotal at the end. Dividers reset variables and tags. Declaration lines count in totals. | The maintainer's notes says so, except declarations in totals (it names a setting, no default). |
| 2026-10-26 | Natural mode ignores unknown words and lists every one. It refuses a dropped stretch that stands where a number should be (`y + 1`, `(y) + 1`, `5 x oops`). It only warns about a word one edit from a unit (`5 kmm`). | `25% tip` must work; a mistyped variable must never become a quiet wrong answer. |
| 2026-10-26 | A lone `x` is the times sign between two operands and a variable name anywhere else. | Variables named `x` are common. |
| 2026-10-26 | Variable names match case-exactly, else case-insensitively when only one variable fits. Declare before use. | The maintainer's notes gives neither rule beyond declare-before-use. |
| 2026-10-26 | Irrational results (sqrt, roots, logs, exp, trig, hyperbolic, pi, tau, phi) are computed to 384 bits (about 115 digits) with correct rounding and returned as a close rational marked approximate. The flag survives every later operation, and `Formatted.exact` is false for it. | Maintainer choice: fixed digits, flagged. |
| 2026-10-26 | A result that is exactly rational stays exact and unflagged: perfect-power roots, `log10(1000)`, `ln(1)`, `exp(0)`, `sin(30 degrees)`, `cos(60 degrees)`, `tan(45 degrees)`, `asind(0.5)` and the rest of the 30/45 degree table. | Precision: never flag what is exact, never claim exactness for what is not. |
| 2026-10-26 | A plain number given to `sin`, `cos`, `tan` is radians; an angle unit or `sind` means degrees. `asin(x)` gives radians as a plain number; `asind(x)` or an argument written in degrees gives degrees. `e` is not a constant (use `exp(1)`). | The trigonometry notes. |
| 2026-10-26 | `rad` is a unit with an approximate factor (180/pi degrees). Converting to or from it is flagged approximate; arithmetic within radians stays exact. | Radians need an irrational factor. |
| 2026-10-26 | Rounding ties go away from zero everywhere (`round(2.5)` is 3, `round(-2.5)` is -3). `x to 2 dp` and `to nearest` produce exact new values, not display rounding. | The maintainer's notes gives no tie rule; this matches the display default. |
| 2026-10-26 | `mod` and `%` between operands keep the sign of the left side (`-7 mod 3` is -1), and work on decimals and same-kind quantities. | The maintainer's notes says "remainder"; floored modulo is ticket 0029. |
| 2026-10-26 | A comma is a list separator. `1,234` is still one number, so write `max(1, 234)` with a space. | Thousands separators win when a comma is followed by exactly three digits. |
| 2026-10-26 | `random number between a and b` uses a seedable generator: whole-number limits give a whole number, otherwise ten decimal places. Tests call `functions::seed_random`. | The one impure function; seedable so it stays testable. |
| 2026-10-26 | A function name with `(` after it is a function even where a unit shares the spelling (`min(1, 2)` versus `5 min`). | `min` is both. |
| 2026-10-26 | Operator precedence follows C: `||`, `&&`, `|`, `xor`, `&`, equality, ordering, shifts, `+ -`, `x / mod`, unary minus, `^`. `and`, `or`, `xor` are logical on true/false and bitwise on whole numbers; `&&` and `||` are logical only; `&` and `|` are bitwise only. `^` stays power. | The maintainer's notes gives the operators but no precedence. |
| 2026-10-26 | Comparisons work on numbers, quantities of one kind (`20km == 20,000 m`), money in one currency and percentages. Booleans compare only for equality. Comparing approximate values that are within 1e-60 of each other is refused. | `sqrt(2) x sqrt(2) == 2` cannot be decided exactly. |
| 2026-10-26 | Conditionals: `if C then A [else B]`, `A if C`, `A unless C`; A and B may be assignments. A false condition with nothing to run gives a line with no answer. A prefix `if` must have a true/false condition; in the suffix form a non-boolean condition falls back to ordinary evaluation (`what if 5 + 5` is 10). | The conditionals page. |
| 2026-10-26 | Bases: `0x`, `0b`, `0o` literals show in their base; `as hex`, `in binary`, `as base N` (2 to 36) set the display base; arithmetic gives decimal, bitwise on two numbers in one base keeps it. Hex digits show in capitals (`0xFF`). Bitwise needs whole numbers of zero or more (negatives are ticket 0034). | The bases page and `255 in hex | 0xFF` on the home page. |
| 2026-10-26 | A declaration line shows money unrounded but with at least the currency's digits (`$45,000.00`, `$1.005`). | The conditionals page shows `earnings = $45k | $45,000.00`. |
| 2026-10-26 | `hp` is mechanical horsepower, 550 ft lbf/s, exactly. | 746 W is a rounding of an exactly defined unit. |
| 2026-10-26 | Finance is exact rational arithmetic. A loan payment uses the standard level-payment formula; total = payment x periods; annual = total / years; monthly = total / (12 x years); daily = total / (365 x years). Compound interest uses (1 + r/m)^(m x t). A fractional exponent is exact when the root is rational and approximate (flagged) otherwise. | The maintainer's own examples ($165.73, $11,932.48, $1,225.04) reproduce to the cent. |
| 2026-10-26 | `X invested Y returned` is Y / X (3x for $500 and $1,500). | The maintainer's text says 2x for that example, which contradicts its own annual-return example; ticket 0040. |
| 2026-10-26 | A sales tax is named in settings with a rate. `$300 + VAT` multiplies by 1 + rate; `$300 - VAT` and `VAT off $300` divide by 1 + rate; `VAT on $300` is the tax added; `VAT in/of/from $300` is the tax contained. | The sales tax page. Regional defaults are ticket 0038. |
| 2026-10-26 | `$24 a day`, `$99 per week` and `90 km over 3 days` are rates. `30 hours at $30/hour` multiplies and `$500 at $20/hour` divides, decided by which side of the rate the units match. | The rates page. |
| 2026-10-26 | Cooking densities, CPI inflation, income-tax tables and regional tax defaults are post-v1 (they are shipped datasets). | Maintainer rule. |
| 2026-10-26 | A date is a count of days since 1970-01-01 in local time; a fraction of a day is the time of day. Date plus a length of time is calendar-aware for months and years (the day clamps: January 31 plus a month is the last day of February) and exact for days, weeks and seconds. Date minus date is a timespan in weeks, days, hours, minutes and seconds, and keeps its sign. | The dates notes. The sign of `January 10 - February 5` is ticket 0041. |
| 2026-10-26 | (Superseded the same day by the Sheet D row below: a year-less date is this year's.) A date written without a year means this year's or next year's occurrence, whichever is closer to today, and never last year's (revised the same day; the first rule here was "the closest occurrence in any year", which on 5 January made `December 28` eight days ago). After `until` or `till` it means the next one, after `since` the last one. | The dates notes: "A date without the year specified may use either the current year or the following year." Not yet confirmed by a maintainer check: `December 28` differs between the two rules only in early January, so it is on the maintainer sheet (Sheet A, position 45) for then. |
| 2026-10-26 | A year is shown only when it is not the current year, so a result prints as `July 1` or `April 4, 2019`. The current year comes from the clock setting, so tests fix the clock. | The dates notes. |
| 2026-10-26 | Workdays are Monday to Friday and a span of them counts the first day and not the last. `workdays in 3 weeks` from a Saturday is 15. `work hours` is workdays times the working-day length (8 by default). No holiday calendar. | The dates notes does not define the end rule; half-open ranges add up across adjacent spans. |
| 2026-10-26 | `A through B` counts both ends. `days between A and B` is the absolute difference. | The dates notes. |
| 2026-10-26 | A year-less Feb 29 resolves to the nearest leap year within two years of today. | A year-less date has to land somewhere; refusing it would be worse. |
| 2026-10-26 | `as <pattern>` on a date, where the pattern is date-format letters (`EEEE, MMM d, yyyy`), uses the NSDateFormatter letters y M d E H h m s a. Any other letter is refused. | The dates notes. |
| 2026-10-26 | A length of time can be written as a timespan (`3 weeks 5 days`), a lap time (`03:04:05`, `00:00:01.5`), or a breakdown (`235 h 12 min`). The choice is carried on the value, so sums and differences of two lap times or two timespans keep it. A fraction of a second that does not end is cut at three places and reported inexact. | The timespans and lap times page. |
| 2026-10-26 | In a run of quantities one after another (`3h 5m 10s`), `m` next to a unit of time is minutes. After an operator it stays meters. | The maintainer's notes example `3h 5m 10s in seconds`. |
| 2026-10-26 | `17:30` and `5:30pm` are times of day. `03:04:05` (two colons) is a lap time. `01:02:03:04` (three colons) is a timecode. | The maintainer's notes says lap times need two colons so they are not read as clock times. |
| 2026-10-26 | Timestamps show every digit with no separators. `X to timestamp` is the local midnight (or the time given) minus the local offset; `to date` reads 100,000,000,000 and up as milliseconds. | The timestamps page. Ticket 0043. |
| 2026-10-26 | A timecode is a length of time in seconds, written with a whole frame rate chosen by `at N fps` anywhere on the line (24 if none). Frame arithmetic uses a `frame` dimension and `fps = frame/s`. | The timecode notes. Ticket 0044. |
| 2026-10-26 | Time zone rules come from the IANA database bundled with `chrono-tz`, never from the machine. The oracle reads the same database release (pip `tzdata==2025.2` is 2025b). | Results must not change with the machine or its tzdata package. |
| 2026-10-26 | A place name is an IANA city, an alias, a country (capital's zone), a region (`eastern time`), an abbreviation (fixed offset) or `GMT+N` / `UTC-N:MM`. Anything else is refused. | The time zones notes. Ticket 0046 lists the choices to confirm. |
| 2026-10-26 | Zone-aware times are an operation on a whole line (`6pm Sydney in Chicago`), not a zone carried on every value, so a zoned time cannot be added to or compared yet. | Keeps every other value simple; revisit if the maintainer's notes needs more. |
| 2026-10-26 | The user's own time zone is a real zone (`local_zone`) with daylight saving, and the fixed offset is only a fallback for tests. A date in another season uses that season's offset. The app reads the zone from `TZ`, then `/etc/localtime`, and shows UTC only when neither names a zone. | `now` and bare times were hours off in the desktop app because nothing set the offset. |
| 2026-10-26 | The app evaluates and formats a sheet inside one settings scope, and reads number format, work hours and zone from `$XDG_CONFIG_HOME/babbage/settings` (`key = value`). `BABBAGE_NOW` fixes the clock and is for tests. | Printing a date reads the clock and zone, so formatting outside the scope used UTC. |
| 2026-10-26 | Number formats are North America (`1,234.56`), Western Europe (`1.234,56`) and Eastern Europe (`1 234,56`, where `.` is also a decimal point). A mark that is not the region's is an error and not a guess (`3.14` in Western Europe). `;` separates function arguments in every format. Underscores group digits in decimal and radix literals (`1_000`, `0xCAFE_F00D`). | The number formats page. |
| 2026-10-26 | A bare `$` means the region's dollar (USD by default). That currency prints with `$`; US dollars elsewhere print `US$`; other dollars keep their own prefix (`A$`). | The region settings and currencies pages. (The volume setting has no effect: ticket 0049.) |
| 2026-10-26 | The app takes zone rules from the machine's zoneinfo, falling back to the bundled 2025b database per zone; the engine defaults to the bundled database so its tests are repeatable. A zone name is read from the folder only if it is plain (no `..`, no leading slash, no empty parts). | Clock rules change by decree, and the bundled copy already differs from newer data for Morocco and western Canada. Ticket 0053. |
| 2026-10-26 | With a workday on either side or in the same expression, calendar days, weeks, months and years count in working time: a week is five workdays and a day is five sevenths of one. Hours and smaller units convert at the work-hours setting (8 by default). Without a workday in play, time is plain calendar time. | The maintainer checked `$500/workday × 4 weeks` = `$10,000.00`; the maintainer's notes give `55h in work days` = 6.875. Ticket 0048. |
| 2026-10-26 | In a sheet a function name is never prose: `sqrt(16)` was answering 16 because natural mode dropped the unknown word `sqrt`. `as timespan`, `as laptime` and `as fraction` are layout words and are not dropped either. | Found by replaying the maintainer's own examples through the sheet evaluator; the oracles only ever ran single lines. |
| 2026-10-26 | `unit in quantity` (`meters in 10 km`, `seconds in a day`) is how many of the left unit the right quantity holds. `X as fraction` is exact and reduced; `N% is B in what` shows `B/(B/N%)` (`1/20`, `1/2.5`). `a is b, what is c` is a x c / b in the kind of a. `X in px at N ppi` counts pixels from inches. | The units, percentages and general pages. |
| 2026-10-26 | The app's settings file takes `tax = VAT 15%` (one word, a rate from 0 to 100). | Sales tax could not be used in the app at all; the engine tests set it in code. |
| 2026-10-26 | Maintainer checks, second pass: a time on today's date prints as just the time (`now` is `12:55 PM`, to the minute); `Yesterday at` and `Tomorrow at` name a day either side; any other day carries its year. `time in X` is always a bare time of day. | The maintainer's `now`, `now + 3 days`, `9:45 am - 15 hours 10 minutes` and `time in Thailand` answers. Supersedes the page's `Tomorrow at 12:30 am`. |
| 2026-10-26 | `PST`, `EST` and the other US abbreviations are their regions with daylight saving; UTC (and GMT, UT, Z) answers for a time of day read on the 24-hour clock (`19:00`). | The maintainer's `noon PST in UTC` is `19:00` and `noon IST in UTC` is `06:30`. Whether CET or BST follow their regions is not known. |
| 2026-10-26 | A week starts on Sunday: `week percentage`, `Tuesday next week`. Percentages of a year or week use real elapsed time. | The maintainer's `week percentage` (22.13% on a Monday afternoon) and `year percentage`. |
| 2026-10-26 | The volume setting has no effect: tbsp, tsp, fl oz, cup, pint, quart and gallon are US customary always; imperial units are named (`imperial pint`). | The maintainer's Imperial and Metric runs gave the US values. Supersedes the earlier volume-system decision. |
| 2026-10-26 | (Superseded by the Sheet D row below: money wins.) The Total of lines that cannot all be added is the sum of the lines of the last unit line's kind, without plain numbers; `X invested Y returned` is the gain over the stake; `A to B` of two plain numbers is their difference. | The maintainer's Sheet C, `$500 invested $1,500 returned` (`2x`) and `10 to 25` (`15`). |
| 2026-10-26 | A name straight against a bracket that is not a function (`foo(45)`) is an error; with a space (`price (5)`) it is prose. Year-less dates inside `midpoint`/`halfway between` are this year's. | The maintainer's `foo(45)` (no answer), `price (5)` (`5`) and `halfway between January 1 and March 1` (`January 31`). |
| 2026-10-26 | Sheet D. A date written without a year is this year's, whatever the month (`January 1` in October is January 1 of this year); `until` and `till` still look ahead and `since` still looks back. | The maintainer's `January 12 + 3 weeks` (`February 2`) and `January 1` (`January 1`). |
| 2026-10-26 | Sheet D. A time of day on its own never shows seconds (`3:45:30 pm` is `3:45 PM`); a date with a time keeps them (`December 10, 2024 at 9:31:23 AM`, from the maintainer's page). | The maintainer's `3:45:30 pm`; the timestamp page. |
| 2026-10-26 | Sheet D. Feet and inches written together (`5 feet 6 inches`, `5 ft 6 in`, `5' 6"`, `6"`) print as words and stay composite through a sum. A part of a pound prints in ounces in the app (`13.5 lb` is `13 lb 8 oz`), but not in the plain ten-place format the oracle corpora use. | The maintainer's `5 feet 6 inches`, `5' 6" + 2 inches`, `6"`, `13.5 lb`. | 2026-10-26 | Sheet D. An hour typed `h` or `hr` keeps that spelling after a slash (`100 km/h`, `60 mph in km/h`); an hour typed `hours` prints `/hour`. The spelling rides on the unit and is ignored by equality. | The maintainer's `100 km/h` against Sheet A's `10 km / 2 hours` (`5 km/hour`). |
| 2026-10-26 | Sheet D. A newton meter prints `N⋅m`. | 2026-10-26 | Sheet D. An amount below 1e-8 is written in scientific form, plain numbers and quantities alike (`1e-9`, `4e-11`). | The maintainer's `0.000000001` and `0.00000000004`. The boundary is a guess: the maintainer's lowest plain decimal is not known. Ticket 0083. |
| 2026-10-26 | Sheet D. The imperial gallon is 4.54609 L and prints `gal`; the imperial pint stays 0.568261 L. | The maintainer's `1 liter in imperial gallons` and `1 imperial gallon in L`. The quart is still twice the pint (not asked). |
| 2026-10-26 | Sheet D. A run of digits joined by two or more dots (`01.05.2005`) is neither a number nor a date; in a sheet it is skipped, as if blank. | 2026-10-26 | Sheet D. A comma straight after a stray word is part of the remark (`hotel, 3 nights x $120` is `$360.00`). Commas between numbers, in function calls and inside dates are separators as before. | The maintainer's `hotel, 3 nights × $120`. |
| 2026-10-26 | Sheet D. A money rate divided by a length of time takes that time as its period: `$500/month / 30 days` is `$16.67/day` (500 / 30, not a unit conversion). | The maintainer's line. Applies only to money rates; `100 m/s / 2 s` is `50 m/s²`. |
| 2026-10-26 | The Total adds the lines in order and starts again from any line that cannot be added to the sum so far; plain numbers join whatever unit the sum has.
